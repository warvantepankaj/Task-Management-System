# Task Management System

A comprehensive, full-stack Task Management System featuring role-based access control (Admin/User), built with FastAPI for the backend and React (Vite) for the frontend.

## 🌟 Features

- **Role-Based Access Control:** Distinct `admin` and `user` roles.
- **User Authentication:** Secure registration and login using JWT (JSON Web Tokens).
- **Task Management:**
  - **Admins** can create, assign, update, delete, and view all tasks.
  - **Users** can view their assigned tasks and update task statuses (`PENDING`, `IN_PROGRESS`, `COMPLETED`).
- **Pagination & Filtering:** Efficiently fetch users and tasks with pagination and status-based filtering.
- **Responsive UI:** Modern, responsive user interface built using React, Tailwind CSS, and Framer Motion.
- **Database Architecture:** Relational schema built with PostgreSQL, featuring dedicated tables for users, tasks, and comments.

## 🏗️ Technology Stack

### Backend
- **Framework:** FastAPI (Python)
- **Database:** PostgreSQL
- **Authentication:** JWT (JSON Web Tokens)

- **Other Utilities:** Password Hashing (passlib/bcrypt)

### Frontend
- **Framework:** React 19 + Vite
- **Styling:** Tailwind CSS + Headless UI
- **Routing:** React Router DOM
- **State/API Management:** Axios, React Hook Form, Zod (Validation)
- **UI Components:** Lucide React, Heroicons, Framer Motion

## 🛠️ Setup Instructions

### 1. Database Setup
Ensure you have PostgreSQL installed and running.
Use the provided `schema.sql` file in the root directory to create the required tables (`users`, `tasks`, `task_comments`) and indexes.
```bash
psql -U your_postgres_user -d your_database_name -f schema.sql
```

### 2. Backend Setup
1. Navigate to the backend directory:
   ```bash
   cd Backend
   ```
2. Create and activate a virtual environment:
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # On Windows use: .venv\Scripts\activate
   ```
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Configure environment variables. Create a `.env` file in the `Backend` directory:
   ```env
   DATABASE_NAME=your_db_name
   DATABASE_USER=your_db_user
   DATABASE_PASSWORD=your_db_password
   DATABASE_HOST=localhost
   DATABASE_PORT=5432
   GEMINI_API_KEY=your_gemini_api_key  # If applicable
   ```
5. Run the FastAPI server:
   ```bash
   uvicorn main:app --reload
   ```
   *The backend will be available at `http://localhost:8000`. API documentation is autogenerated at `http://localhost:8000/docs`.*

### 3. Frontend Setup
1. Navigate to the frontend directory:
   ```bash
   cd Frontend
   ```
2. Install dependencies:
   ```bash
   npm install
   # or
   pnpm install
   ```
3. Start the development server:
   ```bash
   npm run dev
   # or
   pnpm dev
   ```
   *The frontend will run on `http://localhost:5173` (or depending on Vite's default port).*

## 📡 API Endpoints Overview

### Authentication (`/`)
- `POST /register`: Register a new user (`admin` or `user`).
- `POST /login`: Authenticate and receive a JWT access token.

### Users (`/user`)
- `GET /`: Fetch all users (Admin only).
- `GET /id/{id}`: Fetch user by ID (Admin only).
- `GET /email/{email}`: Fetch user by email (Admin only).
- `POST /create_user`: Create a new user (Admin only).
- `GET /paginated`: Fetch users with pagination.

### Tasks (`/tasks`)
- `POST /create_task`: Create a new task and associate it to a user (Admin only).
- `GET /admin`: Fetch all tasks globally (Admin only).
- `GET /user/me`: Fetch tasks assigned to the current logged-in user.
- `PUT /{task_id}/admin`: Fully update a task (Admin only).
- `PATCH /{task_id}/status`: Update only the task's status (User only).
- `GET /filtered`: Fetch tasks using pagination and filters (Status).
- `DELETE /{task_id}/delete`: Delete a specific task (Admin only).

## 🛡️ Security
This project uses **JWT (JSON Web Tokens)** for stateless authentication. Passwords are securely hashed before being stored in standard relational tables. Protected routes rely on dependency injection in FastAPI (`Depends(get_current_user)`, `admin_required`, `user_required`) to extract the user context and enforce Role-Based Access Control (RBAC).
